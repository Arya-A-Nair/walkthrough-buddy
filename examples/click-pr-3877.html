    The big picture

    Click is a library for building command-line programs. You declare options and arguments with decorators, and Click parses sys.argv, prints --help, and reports mistakes. Before this PR, some of those reports named an option by its Python name: The option 'my_option' is deprecated. The user never typed my_option. They typed --my-option.

    The PR gives every parameter one property, Parameter.spec, that returns the user-facing spelling. It moves get_help_spec up from Option to Parameter so arguments have it too. It deprecates the old property human_readable_name, which returned the wrong string for options. It targets Click 8.6.0 (CHANGES.md:9).

    Who notices: end users reading error text, developers whose tests assert on that text, and libraries like cloup that subclass Parameter (the author says so in the PR thread).

    Like you're five

    Think of a coffee shop. The customer writes an order slip (the decls: '-g', '--gluten-free/--no-gluten-free'). The barista turns it into a ticket number for the kitchen (the name: gluten_free). The menu board on the wall shows the drink as the customer orders it (the spec: --gluten-free). Before this PR, when a drink was discontinued, the barista shouted the kitchen ticket number at the customer. Now the barista reads from the menu board.

    Where the analogy breaks: an argument has no flag to order by, so its "menu board" entry is just its name in capitals (RECIPE).

    Glossary

    decls
    The strings a developer passes to @click.option or @click.argument, stored as param_decls. Parsed in src/click/core.py:3449 (options) and src/click/core.py:3963 (arguments).
    name
    The internal id and the keyword the callback receives, like gluten_free. Documented at src/click/core.py:2352.
    opts
    Every spelling that sets the parameter, like ['-g', '--gluten-free']. For an argument it holds the single declaration. src/click/core.py:2359.
    secondary_opts
    The spellings that set a boolean flag to False, the right side of --color/--no-color. src/click/core.py:2370.
    spec
    New. The one spelling users read and type: --times for an option, FILENAME for an argument. src/click/core.py:2570.
    get_help_spec(ctx)
    The longer form shown in the left column of --help, like -c, --config TEXT or [FILENAME].... Now on Parameter at src/click/core.py:2605.
    metavar
    The placeholder shown for a value, like TEXT or FILENAME. Argument.make_metavar adds [...] and ... markers for optional and repeated values.
    prefix
    The leading -, -- or / of a flag, split off by _split_opt in src/click/parser.py:111.
    human_readable_name
    The old property. Deprecated in 8.6.0, removed in 9.0. src/click/core.py:2586.
    error hint
    The quoted parameter text in an error like Missing argument 'RECIPE'. Built by get_error_hint (src/click/core.py:3023) and read by src/click/exceptions.py:150.

    The main path: a deprecated option is used

    Worked example

    Input taken from tests/test_options.py:131, run on the merge commit with an added argument recipe:

    1. @click.option("--my-option", deprecated=True, default="d") builds an Option. _parse_decls sets opts = ['--my-option'] and derives name = 'my_option' (src/click/core.py:3486).
    2. The user runs cli --my-option hello brioche. Command.parse_args calls param.handle_parse_result for each parameter (src/click/core.py:1404).
    3. consume_value returns "hello" with source COMMANDLINE, which is below DEFAULT_MAP, so the deprecation branch runs (src/click/core.py:2960).
    4. self.spec returns '--my-option': the only entry in opts.
    5. stderr gets DeprecationWarning: The option '--my-option' is deprecated., then stdout gets brioche hello. Both lines are the real output I captured.

    Where it can fail

    • Missing argument. Run cli with no args. process_value raises MissingParameter (src/click/core.py:2827), whose message asks Argument.get_error_hint(ctx). That now calls get_help_spec(ctx) and prints Error: Missing argument 'RECIPE'. (captured).
    • Required and deprecated at once. Parameter.__init__ raises ValueError naming the parameter by spec (src/click/core.py:2485).
    • Subclass overrides the old property. The class statement itself emits a DeprecationWarning (src/click/core.py:2392). Click's test config turns every warning into an error (pyproject.toml:86), so this fails tests that define such a subclass.

    Code tour

    1. Parameter.spec: pick the longest prefix

    What it does: returns the declaration with the longest prefix, so --times beats -t. A parameter with no opts falls back to name.

    Why it's built this way

    It mirrors how name is chosen, below, so spec and name come from the same declaration. max() returns the first of equal-length candidates, and the name sort is stable, so ties also agree: ['-t', '--times', '--repeat'] gives --times and times. test_spec asserts that link for every case.

    2. Where name comes from (unchanged)

    What it does: sorts candidate declarations by prefix length and turns the winner into a Python identifier.

    Why it matters

    If you ever change this rule, spec must change with it, or error messages will name a different flag than the one name came from. The one exception is an explicit name: Option(["--times", "repeat_count"]) has name = "repeat_count" and spec = "--times" (tests/test_options.py:123).

    3. Argument.spec: an argument has no flag

    What it does: returns the metavar if the developer gave one, else the name in capitals. This is the body the old Argument.human_readable_name had. Only the name changed.

    4. get_help_spec: the longer help-page form

    What it does: Parameter.get_help_spec returns spec. Option overrides it to join every spelling plus the metavar. Argument overrides it to return make_metavar(ctx), which adds [...] for optional and ... for repeated values.

    Why two methods

    spec needs no context and names the parameter. get_help_spec(ctx) needs a context because the metavar can depend on it, and it decorates the value. The tests pin the difference: nargs=-1 gives spec FILENAME but help spec [FILENAME]... (tests/test_arguments.py:874). Unlike get_help_record, it also works for hidden options (docstring at src/click/core.py:2614).

    5. Error hints switch to the new names

    What it does: the text inside Missing argument '...' or Invalid value for '...'.

    The output is the same string as before for arguments. The point is that nothing inside Click reads human_readable_name any more, so the deprecated property can be deleted in 9.0 without touching callers. The base Parameter.get_error_hint still prefers opts and only falls back to spec (src/click/core.py:3030).

    6. The deprecation message

    What it does: the user-visible change in this PR.

    7. The old property becomes an alias that warns

    What it does: keeps human_readable_name working until 9.0, warns on every read, and returns spec.

    Why stacklevel=2 here

    A property read is one frame from the caller, so a fixed level points at the caller's line. warnings is imported inside the function, which is how the rest of core.py does it (for example src/click/core.py:2396) (inferred: keeps import time down).

    8. Catching subclasses that override the old property

    What it does: at class-definition time, warns if a subclass defines human_readable_name. Click no longer calls it, so such an override would silently stop working.

    Like you're five

    A warning has to point at a line of the user's code. _outside_click_stacklevel walks up the call stack, skipping Click's own frames, until it finds the user. The new skip argument adds abc to the "not the user" list, because Parameter is an ABC and Python's abc module sits between the class statement and __init_subclass__.

    Why at class time

    A read-time warning would never fire, because Click itself no longer reads the property. Only the class definition shows the override (docs/upgrade-guides.md:19).

    Conventions that apply here

    • Warnings are errors in tests (pyproject.toml:86). Any new DeprecationWarning needs a pytest.warns in the test that triggers it.
    • No ternaries: coverage cannot measure both branches (docs/contributing.md:35). Note how Argument.spec uses if and two returns. Older code such as Option.get_help_spec (stop 4) still has a ternary; do not copy it into new code.
    • Wrap Markdown at 80 characters (docs/contributing.md:45).
    • Every change gets a CHANGES.md entry with {pr}`NNNN`, plus .. versionadded:: or .. versionchanged:: in the docstring (.github/pull_request_template.md:23).
    • Deprecations also get a bullet in docs/upgrade-guides.md with the migration path (docs/upgrade-guides.md:19).

    Recipe: change what users see as a parameter's name

    1. Decide whether you need the short form (spec, no context) or the decorated help form (get_help_spec(ctx)). Messages naming a parameter use spec. The help column uses get_help_spec.
    2. For all parameters, edit Parameter.spec at src/click/core.py:2570. For arguments only, edit Argument.spec at src/click/core.py:3932.
    3. If name derivation changes too, keep Option._parse_decls (src/click/core.py:3484) and Parameter.spec choosing the same declaration.
    4. Add a case to test_spec (tests/test_options.py:102) or test_spec_and_help_spec (tests/test_arguments.py:874).
    5. If output wording changes, grep tests for the old string. test_deprecated_warning asserts on it (tests/test_options.py:146).
    6. Add a CHANGES.md bullet under Unreleased and a docstring versionchanged.
    Watch out
    • Do not call human_readable_name from Click code. It warns, and with filterwarnings = error every test that reaches it fails.
    • name is not for users. It is the callback keyword and the source of auto env var names (src/click/core.py:3626), and __repr__ still uses it (src/click/core.py:2525). Changing it breaks callbacks and env vars.
    • Parameter.get_error_hint lists all opts ('-t' / '--times'), not just spec. Only arguments, and options without opts, fall back to spec.
    • An option declared only with a false-side flag has empty opts, so spec falls back to the internal name. I checked: Option(["shout", " /--no-shout"], is_flag=True).spec == "shout".
    • The skip=("abc",) in __init_subclass__ is load-bearing. Without it the warning points inside the abc module, not at the user's class line.

    Check yourself

    An option is declared "-v", "--verbose" and is deprecated. What does the warning name it, and which line decides that?

    '--verbose'. Parameter.spec picks the longest prefix with max() (code tour stop 1), and the warning formats self.spec (stop 6).

    You want --help to show arguments differently. Which method do you change, and which test fails first?

    Argument.get_help_spec (stop 4), which get_help_record calls. test_spec_and_help_spec and test_help_spec_matches_help_record in tests/test_arguments.py pin it.

    A plugin subclasses click.Option and overrides human_readable_name. What happens when it imports, and what happens to its custom value?

    The class statement emits a DeprecationWarning pointing at the plugin's line (stop 8). The custom value is ignored, because Click reads spec. The fix is to override spec.

    What would break if spec picked the first declaration instead of the longest prefix?

    test_spec fails on ["-t", "--times"]: spec would be -t while name is times, and the last assertion that spec maps back to name fails (stop 9).

    Why can you not use name in a new user-facing message?

    It is the Python identifier (my_option), which the user never typed. That is the bug this PR fixed (Before and after).
