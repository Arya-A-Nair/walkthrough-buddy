What this is: Click now names a parameter in messages the way users type it: --my-option, not my_option.

This page: 8 parts, ~20 min. You can stop after any part.

The big picture

One new property, Parameter.spec, now gives the spelling a user types, and Click uses it everywhere it talks to the user.

Click is a library for building command-line programs. You declare options with decorators, and Click parses the command line, prints --help and reports mistakes. Before this PR, some reports named an option by its Python name, which the user never typed: The option 'my_option' is deprecated.

The PR adds Parameter.spec, moves get_help_spec from Option up to Parameter, and deprecates the old property human_readable_name. It ships in Click 8.6.0 (CHANGES.md:9). End users, developers whose tests assert on error text, and libraries that subclass Parameter all see the change.

Like you're five

A customer writes an order slip (the decls: '-g', '--gluten-free/--no-gluten-free'). The barista turns it into a kitchen ticket number (the name: gluten_free). The menu board shows the drink the way customers order it (the spec: --gluten-free).

Before this PR, the barista sometimes shouted the kitchen ticket number at the customer. Now the barista reads from the menu board.

Where the analogy breaks: an argument has no flag to order by, so its menu-board entry is its name in capitals, like RECIPE.

Glossary

Seven words. decls go in, name is for Python, spec is for people.

decls
The strings a developer passes to @click.option or @click.argument. Option parsing: src/click/core.py:3449.
name
The internal id, and the keyword your callback receives, like gluten_free. src/click/core.py:3487.
opts
Every spelling that sets the parameter, like ['-g', '--gluten-free']. An argument stores its single declaration here.
spec
New. The one spelling users read and type: --times for an option, FILENAME for an argument. src/click/core.py:2570.
get_help_spec(ctx)
The longer text in the left column of --help, like [FILENAME].... Now on Parameter at src/click/core.py:2605.
metavar
The placeholder shown for a value, like TEXT or FILENAME.
human_readable_name
The old property. Deprecated in 8.6.0, removed in 9.0. src/click/core.py:2586.
More terms
secondary_opts
Spellings that set a flag to False, the right side of --color/--no-color.
prefix
The leading -, -- or / of a flag, split off by _split_opt.
error hint
The quoted parameter in Missing argument 'RECIPE'. Built by get_error_hint (src/click/core.py:3023), read by src/click/exceptions.py:150.

The main path: a deprecated option is used

The user types a deprecated flag, and Click prints a warning that reads self.spec.

  1. The test input (tests/test_options.py:131) declares --my-option with deprecated=True. I added an argument recipe and ran it on the merge commit.
  2. Command.parse_args calls handle_parse_result for each parameter (src/click/core.py:1404).
  3. The value came from the command line, which ranks below DEFAULT_MAP, so the warning branch runs (src/click/core.py:2963).
  4. self.spec returns '--my-option', the only entry in opts.
  5. stderr gets DeprecationWarning: The option '--my-option' is deprecated. and stdout gets brioche hello. ✅ captured

Where it can fail: run the same command with no arguments. Click prints Error: Missing argument 'RECIPE'. ✅ captured. That text comes from Argument.get_error_hint (src/click/core.py:4008), which now reads get_help_spec.

Extra, skip if busy: two more failure points

  • A subclass that overrides human_readable_name gets a DeprecationWarning at its class line (src/click/core.py:2392). The test config turns warnings into errors (pyproject.toml:86).

Code tour

Six stops: how spec is picked, the argument version, the help form, the one-line fix, and the two deprecation guards.

Stop 1. Parameter.spec picks the longest prefix

What it does: returns the declaration with the longest prefix, so --times beats -t. _split_opt (in src/click/parser.py) splits --times into prefix -- and times. No opts means it falls back to name.

The rule mirrors how name is chosen in Option._parse_decls, so spec and name come from the same declaration:

Why it's built this way

If the two rules differ, an error names a different flag than the one name came from. max() keeps the first of equal-length candidates and the sort is stable, so ties agree too. One exception: an explicit name, as in Option(["--times", "repeat_count"]), gives name = "repeat_count" and spec = "--times" (tests/test_options.py:123).

Stop 2. Argument.spec: an argument has no flag

What it does: returns the metavar if the developer set one, otherwise the name in capitals. The body is the old Argument.human_readable_name; only the method name changed.

Stop 3. get_help_spec: the decorated help form

What it does: Parameter.get_help_spec returns spec (src/click/core.py:2618). Argument overrides it with make_metavar(ctx), which adds [...] for optional and ... for repeated values.

Stop 4. get_help_record puts the help spec in the left column

What it does: the help page builds each argument's row from get_help_spec, so the two always agree.

Why two methods

spec needs no context and names the parameter. get_help_spec(ctx) decorates it, so with nargs=-1 the spec is FILENAME and the help spec is [FILENAME]... (tests/test_arguments.py:874). A second test, test_help_spec_matches_help_record (tests/test_arguments.py:885), checks that the help column equals get_help_spec.

Stop 5. The deprecation message: the user-visible fix

What it does: this one line is why users now see --my-option.

Stop 6. The old property warns, then returns spec

What it does: keeps human_readable_name working until 9.0, with a warning on every read.

stacklevel=2 points the warning at the caller's line, because a property read is one frame away (inferred).

Stop 7. Catching subclasses that override the old property

What it does: when a subclass defines human_readable_name, Python runs __init_subclass__ at the class line, and it warns. Click no longer reads that property, so the override would silently do nothing.

Stop 8. The warning points at the user's class line

What it does: it tells the plugin author which property to override instead, and when the old one goes away.

Like you're five

A warning has to point at a line of your code. _outside_click_stacklevel (src/click/core.py:108) walks up the call stack, skipping Click's own frames, until it finds you. The new skip=("abc",) also skips Python's abc module, which sits between your class line and this hook.

Where the analogy breaks: nothing is "found"; it only counts frames and returns a number.

Extra, skip if busy: the test that pins stop 1

The last assertion maps spec back to name. If spec picked the first declaration instead, ["-t", "--times"] would fail it.

How to contribute here

Make a venv, run three test files, change spec or get_help_spec, add a test and a CHANGES.md line.

Set up and test

  1. Make a venv with Python 3.10 or later (pyproject.toml:16): python3 -m venv .venv. About 1 min. ✅ ran
  2. Activate it: source .venv/bin/activate. Every later command assumes this. 10 s.
  3. Install: pip install -e . pytest. About 1 min. ✅ ran
  4. Run this area: python -m pytest tests/test_options.py tests/test_arguments.py tests/test_deprecations.py. Prints 971 passed in under 1 s. ✅ ran
  5. Run everything: python -m pytest. Prints 2261 passed, 25 skipped, 31000 deselected, 1 xfailed in about 4 s. ✅ ran
  6. Before a PR, run what CI runs: uv run --locked --no-default-groups --group dev tox run (.github/workflows/tests.yaml:39). Time unknown. ⚠️ not run here

All results above are from the merge commit 2247b35. The deselected tests are stress tests, off by default (pyproject.toml:91).

Recipe: change what users see as a parameter's name

  1. Pick the method. Messages use spec; the help column uses get_help_spec(ctx). 2 min.
  2. Edit Parameter.spec (src/click/core.py:2570) for all parameters, or Argument.spec (src/click/core.py:3932) for arguments. 10 min.
  3. Add a case to test_spec (tests/test_options.py:113) or test_spec_and_help_spec (tests/test_arguments.py:874). 10 min.
  4. Search the tests for the old wording. test_deprecated_warning asserts on it (tests/test_options.py:146). 5 min.
  5. Add a CHANGES.md bullet under Unreleased and a .. versionchanged:: line in the docstring. 5 min.

Rules that apply here

  • Warnings are errors in tests (pyproject.toml:86). Every new DeprecationWarning needs a pytest.warns.
  • No ternaries (x if c else y): coverage cannot see both branches (docs/contributing.md:35). Use if and two returns, like Argument.spec.
  • Wrap Markdown at 80 characters (docs/contributing.md:45).
  • Deprecations also get a bullet in docs/upgrade-guides.md with the migration path (docs/upgrade-guides.md:19).
Watch out
  1. Calling human_readable_name from Click code fails tests. It warns, and warnings are errors. Fix: read spec.
  2. name is not for users. It is the callback keyword and the source of auto env var names (src/click/core.py:3626). Fix: change spec, leave name alone.
  3. The PR template says CHANGES.rst (.github/pull_request_template.md:23), but the file is CHANGES.md. Fix: edit CHANGES.md.
Extra, skip if busy: two more gotchas
  • Parameter.get_error_hint lists all opts ('-t' / '--times'), not only spec. It falls back to spec only when opts is empty (src/click/core.py:3030).
  • Removing skip=("abc",) makes the subclass warning point inside Python's abc module instead of the user's class line.

Check yourself

An option is declared "-v", "--verbose" and is deprecated. What does the warning call it, and which line decides?

'--verbose'. Parameter.spec picks the longest prefix with max() (src/click/core.py:2583, code tour stop 1). The warning formats self.spec (stop 5).

You want --help to show arguments differently. Which method do you change, and which tests fail first?

Argument.get_help_spec (stop 3), which get_help_record calls. test_spec_and_help_spec and test_help_spec_matches_help_record in tests/test_arguments.py pin it.

A plugin subclasses click.Option and overrides human_readable_name. What happens?

The class line emits a DeprecationWarning (stops 7 and 8). Click ignores the override, because it reads spec. The fix is to override spec.

What breaks if spec picked the first declaration instead of the longest prefix?

test_spec fails on ["-t", "--times"]: spec would be -t while name is times (stop 1, the collapsed test).
